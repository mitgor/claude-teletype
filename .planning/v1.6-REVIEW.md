# v1.6: Code Review Report

**Reviewed:** 2026-07-18
**Depth:** standard
**Files Reviewed:** 31
**Status:** issues_found

## Summary

Reviewed the v1.6 refactor surface (printing/, rendering/, screens/ packages, fleet detection, catalog profiles, PyInstaller packaging). The refactor structure is sound: the registry/detection/classify seam is clean, catalog citation discipline is consistent, and the packaging scripts fail loudly on missing prerequisites.

Three critical byte-integrity/routing bugs were found. Two are ASCII round-trip corruptions in the driver layer that silently destroy any byte > 0x7F — directly breaking the codepage feature (cp437/cp866) that the catalog work ships. The third is a UI-to-driver contract gap where the macOS "CUPS recommended" path builds a selection that resolves to the simulator driver with no warning. 905 passing tests did not catch these because the corruptions occur only on high-byte payloads and the CUPS-recommendation path requires the macOS kext condition.

## Narrative Findings (AI reviewer)

## Critical Issues

### CR-01: `ProfilePrinterDriver._send_raw` corrupts ESC sequences containing bytes > 0x7F

**File:** `src/claude_teletype/printing/drivers.py:247-255`
**Issue:** `_send_raw` does `data.decode("ascii", errors="replace")` and routes through `self._inner.write(...)`, which re-encodes with `encode("ascii", errors="replace")`. Any byte ≥ 0x80 becomes U+FFFD and then `?` (0x3F) on the wire. This is not hypothetical: the `ppds` profile's `codepage_command` is `b"\x1b[T\x04\x00\x00\x00\x01\xb5"` (profiles.py:215) — the trailing `0xb5` is mangled to `0x3f`, so the printer is told to select code page 1×256+63 = 319 instead of 437. Every `ppds`-derived alias (`ibm`, `lexmark-forms`, `oki-ml-ibm`, `panasonic-kxp-ibm`, `tally-ibm`) is affected, as is any custom TOML profile whose init/reset/style sequences contain high bytes. The subsequent cp437-encoded text then prints as garbage glyphs.
**Fix:** Send raw bytes through the byte channel instead of the str round-trip:
```python
def _send_raw(self, data: bytes) -> None:
    if data:
        self._inner.write_bytes(data)
```
`write_bytes` is part of the `PrinterDriver` protocol and preserves the single-transfer atomicity the docstring requires. (Also fix CR-02 so the CUPS inner driver honors this.)

### CR-02: `CupsPrinterDriver.write_bytes` destroys non-ASCII bytes — codepage printing over CUPS is broken

**File:** `src/claude_teletype/printing/drivers.py:144-153` (with `_flush_line` at 121-132)
**Issue:** `write_bytes` decodes the payload with `data.decode("ascii", errors="replace")` into the line buffer, and `_flush_line` re-encodes with `encode("ascii", errors="replace")`. Every byte ≥ 0x80 becomes `?`. `ProfilePrinterDriver.write` deliberately routes codepage-encoded text (cp437/cp866) through `write_bytes` specifically to bypass ASCII replacement (drivers.py:302-308) — that guarantee is silently voided whenever the inner driver is CUPS (which is the recommended path on macOS per the setup screen). All Cyrillic/box-drawing output over a CUPS queue prints as `?`.
**Fix:** Make the line buffer byte-based (`list[bytes]`), append `char.encode("ascii", errors="replace")` in `write()` and raw `data` in `write_bytes()`, and pass `b"".join(buffer)` directly to `subprocess.run(input=...)` without a decode/encode round trip.

### CR-03: macOS "CUPS recommended" setup path silently produces `NullPrinterDriver`

**File:** `src/claude_teletype/screens/printer_setup.py:263-271, 300-324`; `src/claude_teletype/printing/selection.py:156-161`
**Issue:** When `kernel_driver_holds_printer` fires for a USB entry and CUPS queues exist, the screen sets `radio_cups.value = True` and logs "CUPS Queue selected." But `_on_connect` only populates `cups_printer_name` when `entry["type"] == "cups"` (line 319-321). For a USB entry with the CUPS radio selected, the dismissed selection is `PrinterSelection(connection_type="cups", cups_printer_name=None)`. In `create_driver_for_selection`, the cups branch (`if selection.cups_printer_name:`) skips, `driver` stays `None`, and the user gets `NullPrinterDriver` — the simulator — with no error, on the exact path the UI just recommended. `_save_printer_selection` (tui.py:296-299) then persists `saved_printer_id=""` so the broken state is also saved.
**Fix:** In `_on_connect`, when `connection_type == "cups"` but the entry is a USB device, resolve a CUPS queue name (e.g. serial-matched or first enabled queue from `self._discovery.cups_printers`, mirroring the fallback in `create_driver_for_selection:140-155`), or refuse to dismiss and log an error. Defensively, `create_driver_for_selection` should also treat `connection_type="cups"` with no name as "pick first enabled queue" instead of silently returning the simulator.

## Warnings

### WR-01: `_run_print_pipeline` blocks the Textual event loop; the advertised cancel path cannot fire

**File:** `src/claude_teletype/tui.py:512-618` (esp. 573-579)
**Issue:** The typewriter-mode print pipeline runs synchronously on the event loop with `time.sleep(base_delay * multiplier)` per character. A 5,000-character document at 75ms base delay freezes the entire TUI (no redraw, no input, no escape) for 6+ minutes. The FLOW-05 docstring claims "cancel mid-render leaves the printer style state clean," but the `escape` → `action_cancel_stream` binding can never execute while the loop is blocked — `renderer.close()` in `finally` only covers exceptions, not user cancel. The sync choice is documented as deliberate (Plan 25-02), but combined with the pacer it is now user-visible.
**Fix:** Move the render into a `@work(thread=True)` worker (the pipeline is already sync-friendly) and check `worker.is_cancelled` between characters, or at minimum cap/skip pacing for the in-TUI path until the worker refactor lands.

### WR-02: `teletype.py` — strict ASCII decode, fragmented reset writes, and uncaught Ctrl-C

**File:** `src/claude_teletype/teletype.py:45, 57, 76-78`
**Issue:** Three related defects: (1) line 45 `init_data.decode("ascii")` is strict — a profile whose init/line-spacing/pitch bytes contain ≥ 0x80 crashes with `UnicodeDecodeError` before printing anything (current built-ins are safe; custom TOML profiles are not). (2) Lines 76-78 write `reset_sequence` one byte at a time via `chr(b)` — exactly the fragmented-ESC-transfer failure mode the module docstring says must be avoided ("single USB bulk transfer"), and high bytes are mangled by the driver's ASCII-replace path. (3) `tty.setcbreak` leaves ISIG enabled, so Ctrl-C raises `KeyboardInterrupt` at `sys.stdin.read(1)` instead of being read as `"\x03"`; the exception propagates out of `run_teletype` uncaught (the `ch == "\x03"` check is mostly dead code), producing a traceback despite the docstring's "Ctrl-C exits cleanly."
**Fix:** Use `driver.write_bytes(init_data)` and `driver.write_bytes(profile.reset_sequence)`; wrap the read loop in `except KeyboardInterrupt: pass` (the `finally` already handles restore/formfeed/reset).

### WR-03: `ProfileRegistry.get` lowercases the key but stores keys case-preserved — uppercase custom profiles are unreachable

**File:** `src/claude_teletype/printing/registry.py:89-103`
**Issue:** `get()` looks up `name.lower().strip()` against `self._profiles`, but custom TOML profile names are inserted verbatim (`load_custom_profiles` uses the raw TOML key). A profile named `MyPrinter` appears in `names()` and in the setup screen's Select, yet `registry.get("MyPrinter")` raises ValueError ("Unknown printer profile") because `"myprinter"` is not a key. The `--printer MyPrinter` CLI path fails while listing the exact name the user typed as "available." (`profiles.get_profile` has the same pattern but is safe because all built-in keys are lowercase.)
**Fix:** Normalize at registration: build `self._profiles` with lowercased keys (`{k.lower(): v for ...}`), or look up the raw key first and fall back to the lowercased form.

### WR-04: Picker-mode print path can invoke a blocking `input()` prompt under a running Textual app

**File:** `src/claude_teletype/cli.py:302-306` (via `discover_printer`), `src/claude_teletype/printing/selection.py:38-51`
**Issue:** `MarkdownPickerApp._on_pick` calls `_render_markdown_to_driver`, which calls `discover_printer`, which calls `select_printer` — and with ≥2 CUPS USB queues that function loops on `input()`/`print()`. At that moment Textual owns the terminal (raw mode, alternate screen): the prompt is invisible, keystrokes go nowhere useful, and the app appears hung. tui.py's `_apply_printer_profile` explicitly avoids this ("TUI-safe discovery, no interactive input()"); the picker path does not.
**Fix:** Pass a non-interactive selector into `discover_printer` for the picker path (e.g. auto-select the first enabled queue), or resolve the driver before `picker_app.run()` starts.

### WR-05: "Install USB Support" runs `uv sync` against the current working directory — wrong or destructive outside the repo

**File:** `src/claude_teletype/screens/printer_setup.py:343-381`
**Issue:** `_install_pyusb` executes `uv sync --extra usb` with no `cwd` pinning. Launched from an arbitrary directory (or from the frozen .app, whose Terminal launcher starts in `$HOME`), this syncs whatever `pyproject.toml` happens to be in cwd — potentially mutating an unrelated project's venv — or fails with a confusing error. In the frozen bundle it can never help anyway: the running interpreter's `sys.path` is the bundle, so a venv install is invisible to `_reimport_pyusb`.
**Fix:** Hide the install row when `getattr(sys, "frozen", False)` is true, and pass an explicit project directory (or refuse with a clear message when no `pyproject.toml` is present in the expected location).

## Info

### IN-01: `_render_markdown_to_driver` accepts `all_profiles` but never uses it

**File:** `src/claude_teletype/cli.py:225-232`
**Issue:** The `all_profiles: dict` parameter is threaded through `_print_command_impl`, `_print_command_impl_picker`, and `_make_markdown_picker_app` but is dead inside the renderer helper.
**Fix:** Drop the parameter (and the plumbing) or note why it is reserved.

### IN-02: .app launcher breaks if the bundle path contains a double quote or backslash

**File:** `packaging/make_app.py:49-61`
**Issue:** The single-quote dance protects the shell layer, but `$QUOTED` is interpolated into an AppleScript string delimited by `\"`. A path containing `"` or `\` (user renames/moves the .app) breaks the osascript expression. Low likelihood; worth a comment or an AppleScript-level escape.
**Fix:** Escape `\` and `"` in `$QUOTED` before embedding, or pass the path via `on run argv`.

### IN-03: Misnamed variable `vendor_name` holds the product string

**File:** `src/claude_teletype/printing/discovery.py:161-162`
**Issue:** `vendor_name = dev.product or "Unknown"` — the value is the product descriptor, not the vendor. Diagnostic text is still correct ("Found USB device: ...") but the name misleads maintainers.
**Fix:** Rename to `product_name`.

### IN-04: Inline emphasis toggles on bare `*`/`_` in prose; no escape support

**File:** `src/claude_teletype/rendering/markdown.py:261-299`
**Issue:** `_render_inline` treats every unpaired `*` or `_` as an emphasis toggle: "2 * 3 = 6" opens italic and swallows the `*`; `snake_case_name` toggles italic twice and loses both underscores. `\*` escapes are not honored. Block-boundary close limits the damage to one line, but visible characters are dropped from printed output.
**Fix:** Document as a v1 limitation, or require flanking rules (delimiter adjacent to non-space) before toggling.

### IN-05: `match_saved_printer` matches first VID:PID hit, ignoring serial

**File:** `src/claude_teletype/printing/selection.py:68-83`
**Issue:** With two identical printers attached, smart startup reconnects to whichever enumerates first. `UsbDeviceInfo` carries `serial`, and `_device_matches_identity` prefers it — but the saved-config format only stores `vid:pid`, so the identity precision is lost across restarts.
**Fix:** Store serial in `saved_printer_id` when available (`vid:pid:serial`) and prefer it during matching.

### IN-06: Smoke script leaks a temp HOME per run

**File:** `packaging/smoke_frozen.sh:111`
**Issue:** `HOME="$(mktemp -d)"` in check (5) creates a directory that is never removed.
**Fix:** `TMP_HOME="$(mktemp -d)"; trap 'rm -rf "$TMP_HOME"' EXIT`.
