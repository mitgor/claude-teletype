<objective>
Extend the `PrinterProfile` frozen dataclass with seven new fields — six byte fields for bold/italic/underline on/off codes plus a `buffer_bytes` integer for instant-mode write chunking. This is the foundation Phase 23's renderer (style emission) and Phase 26's instant-mode chunker (buffer-bounded writes) consume as data, so per-printer behavior remains data-driven instead of conditional code (see PROJECT.md Key Decision: "Data-driven printer profiles via frozen dataclass").

Purpose: Enable the markdown renderer in Phase 23 to ask each profile "what byte sequence turns bold on?" without hard-coding any printer family. Empty bytes mean the capability is unsupported and the renderer's fallback chain (added in plan 21-03) takes over.

Output: `src/claude_teletype/profiles.py` gains seven new dataclass fields with documented defaults, and `tests/test_profiles.py` gains coverage proving the fields exist with the right defaults across both `PrinterProfile()` direct construction and the seven canonical built-ins (`generic`, `juki-6100`, `juki-2200`, `escp`, `ppds`, `pcl`, `oki-3390`, `citizen-cts2000`). Plans 21-02 and 21-03 build on top of this.

```python
@dataclass(frozen=True)
class PrinterProfile:
    name: str
    description: str = ""

    # ESC sequences as raw bytes (empty = no-op)
    init_sequence: bytes = b""
    reset_sequence: bytes = b""
    line_spacing: bytes = b""
    char_pitch: bytes = b""

    # Newline strategy
    crlf: bool = False
    reinit_on_newline: bool = False
    reinit_sequence: bytes = b""

    end_of_response_sequence: bytes = b""
    formfeed_on_close: bool = True
    instant_output: bool = False

    # USB auto-detection
    usb_vendor_id: int | None = None
    usb_product_id: int | None = None

    # Paper width
    columns: int = 80
```
