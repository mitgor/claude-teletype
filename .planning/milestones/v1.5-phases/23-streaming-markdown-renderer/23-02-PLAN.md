<objective>
Implement `MarkdownRenderer` in a new module `src/claude_teletype/markdown.py` covering the block-level markdown features MD-02 through MD-07, plus the newline-routing contract MD-08. This is the renderer's core: a hand-written state-machine parser (no external markdown library) that classifies each input line into a block type (heading / list-item / code-fence / blockquote / table-row / paragraph) and emits the rendered character stream through a `text_output_fn` callback.

Plan 23-03 layers inline emphasis (bold + italic) on top via the `style_output_fn` channel; this plan stubs that channel as a no-op default so the block parser can be tested in isolation.

Purpose: Block-level rendering is the structural backbone — headings, lists, code, blockquotes, and tables shape the document; emphasis is decoration. Splitting them lets us land the structural pipeline (and its WordWrapper composition test, the canonical MD-07 gate) before adding inline complexity.

Output: ~250-350 LOC `markdown.py` module + ~200-300 LOC `test_markdown.py` test file with per-feature coverage.

```python
class WordWrapper:
    def __init__(self, width: int, output_fn: Callable[[str], None]) -> None: ...
    def feed(self, char: str) -> None: ...
    def flush(self) -> None: ...
    def reset_column(self) -> None: ...
```

Behavior the renderer must compose with:
- WordWrapper.feed("\n") flushes the current word, emits "\n" through output_fn, resets column.
- WordWrapper.feed(" ") flushes the current word and sets pending_space (deferred until the next char).
- WordWrapper hard-breaks words longer than width.
- WordWrapper does NOT know about prefixes — the renderer must re-emit `> ` (blockquote) or `  ` (nested list indent) at the start of every wrapped continuation by INSERTING the prefix as the first chars after a "\n".

```python
def _wrap(text: str, width: int) -> str:
    """Helper: feed text char-by-char through WordWrapper, return result."""
    collected: list[str] = []
    wrapper = WordWrapper(width, collected.append)
    for ch in text:
        wrapper.feed(ch)
    wrapper.flush()
    return "".join(collected)
```

    `MarkdownRenderer` exposes:
    - `__init__(self, text_output_fn, style_output_fn=None, profile=None, columns=80)`
      - `text_output_fn: Callable[[str], None]` — required; receives every plain character INCLUDING newlines
      - `style_output_fn: Callable[[bytes], None] | None` — optional; defaults to a no-op lambda
      - `profile: PrinterProfile | None` — optional; defaults to None (Plan 23-03 uses it for resolve_style)
      - `columns: int` — line width used for table layout (defaults to profile.columns when profile is present, else 80)
    - `render(self, text: str) -> None` — main entry point. Splits text into lines and dispatches each line to the active block parser (paragraph by default, switches to code/table/blockquote on detection).

    Block detection rules (state machine):
    - **Fenced code block:** a line whose stripped form is exactly `` ``` `` (optionally followed by a language tag) toggles code-block mode. Inside code mode, every line is emitted as `"    " + line + "\n"` through text_output_fn with NO inline emphasis processing (Plan 23-03 will skip emphasis when in code mode). Closing `` ``` `` returns to normal mode.
    - **ATX heading:** a line starting with `#` (1-6) followed by a space. Strip leading `#`s, strip trailing `#`s, strip surrounding spaces. Emit a leading `\n` (blank line above), then the heading text, then `\n\n` (heading newline + trailing blank line). Plan 23-03 wraps the heading text in style_on/style_off bold bytes; this plan emits plain text only.
    - **Blockquote:** a line starting with `>`. Strip the `>` and at most one following space, then render the remaining content as a paragraph WITH a per-line `"> "` prefix that re-emits at the start of every continuation line. This plan implements the prefix; the WordWrapper-composition behavior is verified in Task 2.
    - **Unordered list item:** a line whose first non-space char is `-`, `*`, or `+` followed by a space. Compute indent_level = (count of leading spaces) // 2. Emit `("  " * indent_level) + "* " + content + "\n"`. Continuation prefix for wrapping is `"  " * indent_level + "  "` (4 spaces total at indent 0 — aligns under the bullet's content column).
    - **Ordered list item:** a line whose first non-space chars match `^\s*(\d+)\.\s` (regex). Emit `("  " * indent_level) + "{num}. " + content + "\n"`. Continuation prefix mirrors the unordered case.
    - **GFM table:** detect by a header line containing `|` and a delimiter line (next line) matching `^\s*\|?\s*:?-+:?\s*(\|\s*:?-+:?\s*)+\|?\s*$`. When detected, buffer subsequent rows until a non-table line, then render as ASCII grid (Task 1 implements detection + buffering; ASCII grid rendering is a sub-method `_render_table(rows: list[list[str]]) -> None`).
    - **Paragraph (default):** emit text + `\n` after each line; consecutive non-empty paragraph lines are joined with a space (markdown-standard line-folding) — but for simplicity in v1 of the renderer, emit each paragraph line as-is followed by `\n`. (Most markdown documents use blank-line-separated paragraphs anyway.)

    State to track between lines:
    - `_in_code_block: bool`
    - `_table_buffer: list[str]` — raw rows being collected
    - `_pending_blank: bool` — whether the previous line was blank (used to coalesce paragraph blocks)

    Newline routing (MD-08): every newline emitted by the renderer goes through `text_output_fn("\n")`. The renderer NEVER calls `style_output_fn(b"\n")`. This is enforced by code review and tested in Task 2.

    Inline emphasis (MD-01) is NOT implemented in this plan — `_render_inline(text: str) -> None` is a stub that emits each character through text_output_fn. Plan 23-03 will replace this method with the bold/italic state machine.

      WordWrapper.feed() so wrapping happens downstream.
