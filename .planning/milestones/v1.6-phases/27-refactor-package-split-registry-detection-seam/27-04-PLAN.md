<interfaces>
Registry shape (ARCHITECTURE §A; exact API at Claude's discretion):
- `ProfileRegistry(builtins: dict[str, PrinterProfile], custom: dict[str, PrinterProfile] | None = None)` — constructor merges `{**builtins, **(custom or {})}` (custom overrides built-in) and builds exact `(vid,pid)->name` and `vid->name` indices once.
- `get(name: str) -> PrinterProfile` — replaces `printing.profiles.get_profile`
- `names() -> list[str]`
- `match_vidpid(vid: int, pid: int) -> PrinterProfile | None` — exact match takes priority over vid-only; replaces `auto_detect_profile` map-building
- `all() -> dict[str, PrinterProfile]`

Canonical duplicated-logic call sites being consolidated (27-PATTERNS.md "Analog"):
1. printing.profiles.auto_detect_profile (the exact/vid-only map-build, ~lines 486-524)

3. screens/printer_setup._match_profile_by_vid_pid (4th re-implementation)
4. cli merge `dict(BUILTIN_PROFILES); .update(custom)` — appears in _resolve_print_context (~447) and main (~792)

Aliases to preserve (built via dataclasses.replace in printing.profiles BUILTIN_PROFILES, ~lines 291-303): `ibm`←`ppds`, `juki`←`juki-6100`. Registry must keep these names resolvable. Catalog/ split is OUT OF SCOPE (Phase 29) — wrap the existing BUILTIN_PROFILES dict, do not restructure it.
