<feature>
  <name>Configuration Module (TeletypeConfig + load/save/merge)</name>
  <files>src/claude_teletype/config.py, tests/test_config.py, pyproject.toml</files>
  <behavior>
    The config module provides a three-layer merge system: defaults < TOML file < env vars < CLI flags.

    **TeletypeConfig dataclass fields and defaults:**
    - delay: float = 75.0
    - no_audio: bool = False
    - no_tui: bool = False
    - transcript_dir: str = "transcripts"
    - device: str | None = None
    - juki: bool = False

    **Test cases (RED phase):**

    1. TeletypeConfig() returns instance with correct defaults
       - TeletypeConfig().delay == 75.0
       - TeletypeConfig().no_audio == False
       - TeletypeConfig().device is None

    2. load_config returns defaults when file does not exist
       - load_config(Path("/nonexistent/path/config.toml")) == TeletypeConfig()

    3. load_config reads TOML sections and populates dataclass
       - Given TOML with `[general]\ndelay = 50.0\n[printer]\njuki = true`
       - load_config(path) returns TeletypeConfig(delay=50.0, juki=True)

    4. load_config ignores unknown TOML keys gracefully
       - Given TOML with `[general]\nfuture_key = "value"`
       - load_config(path) returns TeletypeConfig() (defaults, no error)

    5. apply_env_overrides reads CLAUDE_TELETYPE_DELAY
       - Set CLAUDE_TELETYPE_DELAY="50" in env
       - apply_env_overrides(TeletypeConfig()).delay == 50.0

    6. apply_env_overrides handles boolean env vars
       - Set CLAUDE_TELETYPE_NO_AUDIO="true" in env
       - apply_env_overrides(TeletypeConfig()).no_audio == True
       - Set CLAUDE_TELETYPE_NO_AUDIO="0" in env
       - apply_env_overrides(TeletypeConfig()).no_audio == False

    7. apply_env_overrides handles string env vars (device)
       - Set CLAUDE_TELETYPE_DEVICE="/dev/usb/lp0"
       - apply_env_overrides(TeletypeConfig()).device == "/dev/usb/lp0"

    8. merge_cli_flags overrides only non-None values
       - merge_cli_flags(TeletypeConfig(), delay=50.0, no_audio=None).delay == 50.0
       - merge_cli_flags(TeletypeConfig(), delay=50.0, no_audio=None).no_audio == False (unchanged)

    9. write_default_config creates file with commented TOML template
       - write_default_config(tmp_path / "config.toml") creates the file
       - File content contains "[general]", "[printer]", "delay = 75.0"
       - File is valid TOML (tomllib.load succeeds)
       - Parent directories are created if missing

    10. CONFIG_FILE uses platformdirs for platform-specific path
        - CONFIG_FILE path contains "claude-teletype"
  </behavior>
  <implementation>
    1. Add `tomli-w>=1.2.0` and `platformdirs>=4.0.0` to pyproject.toml dependencies using `uv add tomli-w platformdirs`.

    2. Create `src/claude_teletype/config.py` following the research Example 1 pattern:
       - Import `tomllib` (stdlib), `os`, `dataclasses`, `Path`, `platformdirs.user_config_path`
       - Define constants: APP_NAME, CONFIG_DIR, CONFIG_FILE, ENV_PREFIX
       - Define TeletypeConfig dataclass with 6 fields
       - Define DEFAULT_CONFIG_TEMPLATE as a raw string constant with TOML comments (NOT generated by tomli-w, since tomli-w cannot write comments)
       - Implement load_config(config_path: Path | None = None) -> TeletypeConfig
       - Implement apply_env_overrides(config: TeletypeConfig) -> TeletypeConfig
       - Implement merge_cli_flags(config: TeletypeConfig, **flags) -> TeletypeConfig
       - Implement write_default_config(config_path: Path | None = None) -> Path

    3. Type handling in apply_env_overrides:
       - Use `f.type` to check field types. Note: for `str | None`, f.type is `str | None` not `str`. Handle union types by checking `hasattr(f.type, '__args__')` or use string comparison.
       - float fields: float(env_val)
       - bool fields: env_val.lower() in ("1", "true", "yes")
       - str/Optional[str] fields: direct assignment

    4. The DEFAULT_CONFIG_TEMPLATE string must be valid TOML when parsed (i.e., commented-out keys like `# device = "/dev/usb/lp0"` are fine, but the uncommented keys must parse correctly).
  </implementation>
</feature>
