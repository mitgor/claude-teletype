<objective>
Fix the integration gap where system_prompt is silently dropped when switching backends via the settings modal. Add _system_prompt as a tracking attribute on TeletypeApp (same pattern as _backend_name, _model_config), pass it from cli.py, and thread it through create_backend() in _apply_settings.

Purpose: Without this fix, users who configure a system_prompt in their TOML config lose it on any backend or model change via the settings modal. This is the last v1.2 gap closure.
Output: Working bug fix with TDD test coverage proving system_prompt survives backend hot-swap.
</objective>

    When a user has system_prompt configured (e.g. "You are a helpful assistant.") and switches
    backends or models via the settings modal, the system_prompt MUST be passed to create_backend()
    so the new backend uses it.

    - TeletypeApp(system_prompt="You are a helpful assistant.") -> _apply_settings(backend="openrouter", model="openai/gpt-4o") -> create_backend called with system_prompt="You are a helpful assistant."
    - TeletypeApp(system_prompt="You are a helpful assistant.") -> _apply_settings(same backend, different model) -> create_backend called with system_prompt="You are a helpful assistant."
    - TeletypeApp(system_prompt="") -> _apply_settings(new backend) -> create_backend called with system_prompt=None (empty string treated as None, matching cli.py pattern)
  </behavior>
